# 采样器原理与实现差异

本文说明扩散模型、流匹配模型中常见采样器的核心原理、差异和实现形式。重点以 DiffSynth-Studio 当前代码为基准，同时补充 DDPM、DDIM、Euler、Heun、DPM-Solver、UniPC、FlowMatch、Flash re-noise 等方法的直观理解。

阅读本文时可以先记住一句话：

```text
生成不是一次性把噪声变成图像，而是在 latent 空间里沿着一条“从噪声到数据”的轨迹逐步移动。
```

采样器要回答三个问题：

| 问题 | 对应概念 | 例子 |
| --- | --- | --- |
| 当前处在多脏的噪声层级？ | timestep / sigma / alpha | `t=800`、`sigma=0.8`、`alpha_bar=0.1` |
| 下一步走到哪里？ | scheduler / noise schedule | `1000 -> 900 -> 800` 或 `sigma: 1.0 -> 0.8 -> 0.6` |
| 这一小步怎么走？ | sampler / numerical solver | DDIM、Euler、Heun、DPM-Solver、UniPC |

在 DiffSynth-Studio 里，入口通常收敛到：

```python
scheduler.set_timesteps(num_inference_steps)
x = init_noise()
for progress_id in range(num_inference_steps):
    timestep = scheduler.timesteps[progress_id]
    model_output = model(x, timestep, condition)
    x = scheduler.step(model_output, timestep, x)
image = vae.decode(x)
```

因此源码层面看采样器，最关键的是两个函数：

| 函数 | 作用 |
| --- | --- |
| `set_timesteps()` | 决定走哪些噪声点，也就是“路线规划”。 |
| `step()` | 决定每一步如何更新 latent，也就是“走路方式”。 |

## 1. 直观模型：采样是在 latent 空间里“导航”

可以把 latent 想象成一个高维坐标点。

```text
纯噪声 latent                 干净图像 latent
     x_T  ---------------------->  x_0
      |                              |
      | 很乱、没有语义                 | 有结构、有语义
      |                              |
   sigma 大 / t 大              sigma 小 / t 小
```

模型每次看到的是：

```text
当前 latent + 当前噪声强度 + 文本/图像/视频/音频条件
```

然后输出一个“应该如何修正当前 latent”的量。采样器拿到这个输出之后，把它转成下一步 latent。

关键点在于：模型输出本身不是天然等于“下一张图”。它可能表示不同含义：

| 模型输出 | 含义 | 常见于 |
| --- | --- | --- |
| `epsilon` | 当前 noisy latent 里混入的噪声 | DDPM / DDIM / SD 系列 |
| `x0` | 直接预测干净 latent | 一些扩散变体 |
| `v_prediction` | DDPM 参数化下的速度变量 | SD 2.x、部分视频模型 |
| `velocity = noise - data` | Flow Match 从数据指向噪声的速度场 | Wan / FLUX / Qwen / Z-Image 等 |
| `score` | log probability 对样本的梯度，指向更高概率区域 | score-based diffusion / SDE |

所以采样器不能只看名字换。它必须知道模型输出到底代表什么，否则 `step()` 会把方向、尺度或时间变量解释错。

一个直观类比：

```text
模型输出 = 导航系统给出的指令
采样器   = 你采用的驾驶策略
日程     = 要经过哪些路口
```

如果导航说的是“向东走 100 米”，你却把它理解成“目的地坐标是东边 100 米”，路线就会错。采样器和模型训练目标不匹配时，本质上就是这种错位。

## 2. 前向加噪：训练时先构造“脏样本”

采样的反方向是训练时的加噪过程。理解采样器，必须先理解模型训练时看到的输入是什么。

### 2.1 DDPM / DDIM 的 alpha 形式

传统扩散模型把干净样本 `x0` 和标准噪声 `epsilon` 混合：

```text
x_t = sqrt(alpha_bar_t) * x0 + sqrt(1 - alpha_bar_t) * epsilon
```

这里：

| 变量 | 含义 |
| --- | --- |
| `x0` | 干净 latent |
| `epsilon` | 标准高斯噪声 |
| `alpha_bar_t` | 到 timestep `t` 为止保留下来的信号比例 |
| `sqrt(alpha_bar_t)` | 干净信号权重 |
| `sqrt(1 - alpha_bar_t)` | 噪声权重 |

当 `t` 越大，`alpha_bar_t` 通常越小：

```text
t 小: x_t 接近 x0
t 大: x_t 接近 epsilon
```

DiffSynth-Studio 的 `DDIMScheduler.add_noise()` 对应：

```python
noisy_samples = sqrt_alpha_prod * original_samples + sqrt_one_minus_alpha_prod * noise
```

这类模型常见训练目标是预测 `epsilon`：

```python
target = noise
```

如果使用 `v_prediction`，目标会变成：

```python
target = sqrt_alpha_prod * noise - sqrt_one_minus_alpha_prod * sample
```

注意：这里的 `v_prediction` 是 DDPM 参数化下的 `v`，不要和 Flow Match 里的 `velocity = noise - data` 混为一谈。

### 2.2 Flow Match 的 sigma 插值形式

Flow Match 使用更直接的线性插值：

```text
x_sigma = (1 - sigma) * x0 + sigma * noise
```

当：

```text
sigma = 0 -> x_sigma = x0
sigma = 1 -> x_sigma = noise
```

DiffSynth-Studio 的 `FlowMatchScheduler.add_noise()` 对应：

```python
sample = (1 - sigma) * original_samples + sigma * noise
```

训练目标是：

```python
target = noise - sample
```

这里源码里的 `sample` 表示干净训练样本，也就是上文的 `x0`。因此可以写成：

```text
target = noise - x0
```

这个目标可以理解为一条直线轨迹的速度：

```text
x_sigma = x0 + sigma * (noise - x0)
```

对 `sigma` 求导：

```text
d x_sigma / d sigma = noise - x0
```

所以 Flow Match 模型学的是“沿 sigma 方向，从干净样本走向噪声样本的速度”。推理时我们反过来，从大 `sigma` 走向小 `sigma`，就能从噪声回到数据。

### 2.3 一个数字例子：DDIM 与 Flow Match 的加噪差异

假设：

```text
干净样本 x0 = 2
噪声 noise = 10
```

DDIM / DDPM 形式，如果 `alpha_bar_t = 0.25`：

```text
x_t = sqrt(0.25) * 2 + sqrt(0.75) * 10
    = 0.5 * 2 + 0.866 * 10
    = 9.66
```

Flow Match 形式，如果 `sigma = 0.75`：

```text
x_sigma = (1 - 0.75) * 2 + 0.75 * 10
        = 0.25 * 2 + 0.75 * 10
        = 8.0
```

两个过程都在混合数据和噪声，但坐标系统不一样：

| 方法 | 使用的噪声坐标 | 混合形式 |
| --- | --- | --- |
| DDPM / DDIM | `alpha_bar_t` | 平方根加权 |
| Flow Match | `sigma` | 线性插值 |

这就是为什么 Flow Match 模型不能直接拿 DDIM 公式采样。DDIM 的公式假设模型输出和 `alpha_bar_t` 坐标匹配；Flow Match 的公式假设模型输出和 `sigma` 坐标匹配。

## 3. 反向采样：从“脏样本”回到“干净样本”

训练时是：

```text
干净样本 -> 加噪 -> 脏样本
```

推理时是：

```text
随机噪声 -> 逐步去噪 -> 干净样本
```

采样器的难点在于：模型每次只能基于当前点估计一个局部信息，而完整轨迹是连续变化的。

这和数值求解微分方程相同：

```text
dx / dt = f(x, t)
```

模型近似提供 `f(x, t)`，采样器用不同方法把许多小步拼起来。

```text
Euler:     只看当前位置的斜率，直接走一步
Heun:      先走一步看看新位置斜率，再平均修正
DPM:       利用扩散 ODE 的结构和历史斜率做高阶近似
UniPC:     预测一步，再用校正器修正
DDIM:      先估计 x0，再按下一噪声强度重组
FlowMatch: 在 sigma 空间沿速度场积分
```

直观上：

```text
一步采样 = 在高维空间里画一小段线
多步采样 = 用很多小线段拼出从噪声到图像的曲线
```

更高阶的采样器，就是试图用更聪明的小线段逼近这条曲线。

### 3.1 一个形象例子：修复被不同厚度雾遮住的海报

把生成过程想象成修复一张海报。

```text
x0        = 原始清晰海报
noise     = 一整张随机噪声图
sigma     = 雾的厚度
x_sigma   = 被雾遮住后的海报
condition = 文字描述，例如“一个人在海边弹吉他”
```

训练时，系统不是从纯噪声一路生成到清晰海报，而是反复做这样的监督题：

```python
x0 = sample_clean_latent_from_dataset()
noise = torch.randn_like(x0)
sigma = sample_noise_level()

x_sigma = (1 - sigma) * x0 + sigma * noise
pred = model(x_sigma, sigma, condition)
target = noise - x0
loss = mse(pred, target)
```

这像是在训练一个修复师。每次给他看一张“不同雾量”的海报，并告诉他正确答案：

```text
当前雾图应该往哪个方向修，才能回到清晰海报。
```

训练时的“采样”主要有三层含义：

| 训练时采样了什么 | 直观含义 | 目的 |
| --- | --- | --- |
| 采样数据 `x0` | 从数据集中拿一张清晰海报 | 覆盖不同内容、姿态、运动、风格 |
| 采样噪声 `noise` | 随机生成一层雾 | 让模型知道不同随机扰动下怎么修 |
| 采样噪声层 `sigma/timestep` | 随机决定雾有多厚 | 让模型学会从厚雾、中雾、薄雾中分别修复 |

训练时的去噪并不是完整执行：

```text
x_1.0 -> x_0.8 -> x_0.6 -> x_0.4 -> x_0.2 -> x0
```

而是随机抽一道单点题：

```text
给你 x_0.8，告诉我这里的修复方向。
给你 x_0.4，告诉我这里的修复方向。
给你 x_0.1，告诉我这里的修复方向。
```

这很关键。训练阶段通常知道真实 `x0`，所以可以直接构造任意噪声层的监督信号；推理阶段不知道 `x0`，只能从纯噪声开始一步步靠模型自己走出来。

### 3.2 推理时不同采样器在这个例子里的作用

推理时没有原始清晰海报，只有一张纯噪声海报：

```text
x_1.0 = noise
```

模型每次只能根据当前雾图和文字条件，判断“该往哪个方向修”。采样器决定如何使用这个判断。

| 采样器 | 在修复海报例子中的行为 | 数学形状 |
| --- | --- | --- |
| FlowMatch Euler | 看当前雾图，只按当前方向修一小步。 | `x_next = x + v * delta_sigma` |
| DDIM | 先估计清晰海报，再按下一层雾厚重新组合。 | `x0_pred -> x_prev` |
| Heun | 先试修一步，再看试修后方向，最后取平均。 | `0.5 * (d1 + d2)` |
| DPM-Solver | 利用当前和历史修复方向，用高阶公式估计更准的一步。 | history / high-order update |
| UniPC | 先预测下一张雾图，再用校正器修正。 | predictor + corrector |
| Flash re-noise | 先估计清晰海报，再主动加回受控的下一层雾。 | `x0_pred + controlled_noise` |

用 Flow Match 的数字例子表示：

```text
真实清晰海报 x0 = 2
随机雾 noise = 10
真实方向 v = noise - x0 = 8
当前 sigma = 0.75
当前雾图 x_0.75 = 8
```

如果模型预测完全准确，直接一步到 `x0`：

```text
x0 = x_0.75 + v * (0 - 0.75)
   = 8 + 8 * (-0.75)
   = 2
```

但真实模型经常不是 `v=8`，而可能预测成 `v=7.2` 或 `v=8.6`。如果一步跳到 `sigma=0`：

```text
v_pred = 7.2
x0_pred = 8 + 7.2 * (0 - 0.75)
        = 2.6
```

这个误差会直接变成最终结果。多步则不同：

```text
x_0.75 --修一点--> x_0.50 --重新判断--> x_0.25 --重新判断--> x_0
```

每走一步，海报更清楚一点，模型看到的信息也更可靠一点。中间重新判断的机会，就是多步采样的价值。

### 3.3 一步到 `x0` 与多步到 `x0` 的本质区别

从公式看，一步到 `x0` 很诱人。Flow Match 下只要有：

```text
x_sigma = x0 + sigma * v
```

就能写出：

```text
x0 = x_sigma - sigma * v
```

如果 `v` 是真值，一步当然成立。但推理时 `v` 是模型猜的，而且噪声越大，猜测越难。

可以把区别压缩成这张表：

| 方式 | 实际含义 | 依赖什么 | 主要风险 |
| --- | --- | --- | --- |
| 一步到 `x0` | 在高噪声点做一次大跨度全局猜测 | 当前点的一次模型输出必须足够准 | 错误被整段放大，结构和细节都没机会修正 |
| 多步到 `x0` | 把大问题拆成多个局部修复问题 | 每一步只需要局部方向相对可靠 | 更慢，但可以逐步修正 |

不同噪声阶段承担的任务也不同：

| 噪声阶段 | 海报例子 | 生成任务中的作用 |
| --- | --- | --- |
| 高噪声 | 只能看出大概轮廓 | 决定主体、布局、视频运动趋势 |
| 中噪声 | 姿态和结构开始清楚 | 修正位置关系、动作、时序一致性 |
| 低噪声 | 细节逐渐可见 | 补纹理、边缘、局部细节 |

一步到 `x0` 等于让模型在高噪声阶段同时完成所有阶段的事。普通模型通常没有被训练成这么做，所以直接一步生成容易糊、结构飘、细节不稳。

少步模型、Turbo、Lightning、Flash、Consistency Model 这类方法能减少步数，是因为训练阶段额外做了蒸馏或一致性约束，把多步老师模型的行为压缩进少数几步里。它不是普通采样器简单少走几步就能稳定得到的能力。

### 3.4 为什么训练时不直接按推理的固定间隔训练

这个问题可以拆成两种情况。

第一种：只在固定噪声点上训练局部方向。

```text
只训练 sigma = 1.0, 0.8, 0.6, 0.4, 0.2
```

这当然可以做。但它训练的仍然是：

```text
给定真实加噪得到的 x_sigma，预测当前点的修复方向。
```

问题是训练和推理看到的点不完全一样：

```text
训练看到的是：x_sigma = (1 - sigma) * x0 + sigma * noise
             这是落在真实加噪轨迹上的点。

推理看到的是：x_sigma 来自模型前几步自己走出来的结果
             它可能已经偏离真实轨迹。
```

这类似老师批改练习题时，学生每道题都从标准题面开始；但真正考试时，学生上一题的错误会影响下一题的题面。多步采样中的每一步误差会累积，因此只在固定点做局部监督，并不等于模型已经学会了从自己产生的偏差中恢复。

第二种：直接训练大步跳转。

```text
训练 model(x_1.0) -> x_0.8
训练 model(x_0.8) -> x_0.6
甚至训练 model(x_1.0) -> x0
```

这也可以做，但已经接近少步蒸馏、一致性模型或 rectified flow distillation 的范畴。难点有三点：

| 难点 | 原因 |
| --- | --- |
| 大步目标更模糊 | 高噪声里保留的信息很少，同一个噪声输入可能对应多个合理清晰结果。 |
| 分布偏移更明显 | 训练用的跳转起点通常是标准加噪点，推理中是模型自己走出的点。 |
| 泛化弹性下降 | 如果只训练固定间隔，换步数、换日程、换分辨率或换任务时更容易失配。 |

因此，普通扩散或 Flow Match 训练更常见的策略是：

```text
训练阶段：随机覆盖大量噪声层，学一个较连续的局部修复方向场。
推理阶段：根据速度和质量需求，选择一条离散噪声日程，用采样器沿方向场积分。
```

而少步蒸馏模型的策略是：

```text
先有一个多步老师模型，能稳定走完整轨迹；
再训练学生模型模仿老师在少数几个大步上的结果；
最后推理时才能用很少步数生成。
```

所以“训练时直接按固定间隔训练”不是不可行，而是它改变了训练目标：从学习通用的局部方向场，变成学习某条固定少步轨迹。前者更通用，后者更快但更依赖专门训练和固定配置。

## 4. Scheduler 与 Sampler 的区别

很多代码库会把 `scheduler` 和 `sampler` 混用，但更准确地说它们是两层概念。

| 概念 | 负责什么 | 直观理解 | 代码体现 |
| --- | --- | --- | --- |
| 噪声日程 scheduler | 选择哪些噪声点 | 路线经过哪些站点 | `set_timesteps()` / `sigmas` / `timesteps` |
| 数值积分 sampler | 每两个噪声点之间怎么走 | 两站之间如何移动 | `step()` |

比如同样是 Flow Match，一条路线可以是：

```text
sigma: 1.0 -> 0.8 -> 0.6 -> 0.4 -> 0.2 -> 0.0
```

也可以是：

```text
sigma: 1.0 -> 0.92 -> 0.78 -> 0.55 -> 0.25 -> 0.0
```

如果 `step()` 仍然是：

```python
x_next = x + velocity * (sigma_next - sigma)
```

那 sampler 没变，变的是 scheduler。

反过来，如果噪声点一样，但一步更新从 Euler 换成 Heun：

```python
x_predict = x + d1 * dt
d2 = model(x_predict, t_next)
x_next = x + 0.5 * (d1 + d2) * dt
```

那 scheduler 没变，变的是 sampler。

## 5. DiffSynth-Studio 中的 FlowMatchScheduler

源码：`diffsynth/diffusion/flow_match.py`

### 5.1 核心公式

Flow Match 的训练构造：

```python
x_sigma = (1 - sigma) * x0 + sigma * noise
target = noise - x0
```

推理更新：

```python
x_next = x + model_output * (sigma_next - sigma)
```

源码对应：

```python
def step(self, model_output, timestep, sample, to_final=False, **kwargs):
    timestep_id = torch.argmin((self.timesteps - timestep).abs())
    sigma = self.sigmas[timestep_id]
    if to_final or timestep_id + 1 >= len(self.timesteps):
        sigma_ = 0
    else:
        sigma_ = self.sigmas[timestep_id + 1]
    prev_sample = sample + model_output * (sigma_ - sigma)
    return prev_sample
```

因为推理是从 `sigma` 大走到 `sigma` 小，所以：

```text
sigma_next - sigma < 0
```

模型输出如果是 `noise - x0`，乘上负的步长，就会把样本往 `x0` 方向拉回去。

### 5.2 为什么这个公式能把噪声拉回数据

仍然用数字例子：

```text
x0 = 2
noise = 10
velocity = noise - x0 = 8
```

在 `sigma = 0.75` 时：

```text
x_sigma = x0 + sigma * velocity
        = 2 + 0.75 * 8
        = 8
```

如果下一步到 `sigma_next = 0.5`：

```text
x_next = x_sigma + velocity * (sigma_next - sigma)
       = 8 + 8 * (0.5 - 0.75)
       = 6
```

而真实的 `sigma=0.5` 位置正好是：

```text
x_0.5 = 2 + 0.5 * 8 = 6
```

如果模型预测完全准确，Euler 一步就能落在直线轨迹上的正确位置。真实模型不可能完全准确，且高维条件下轨迹并不总是简单直线，所以需要多个步骤逐渐修正。

### 5.3 Flow Match 中的 `x0` 和 `noise` 可以互相还原

由于：

```text
x_sigma = x0 + sigma * v
v = noise - x0
```

如果模型输出 `v`，就可以估计：

```text
x0_pred    = x_sigma - sigma * v
noise_pred = x_sigma + (1 - sigma) * v
```

这解释了为什么 Flash re-noise 可以先做：

```python
denoised = sample - model_output * sigma
```

它其实是在估计 `x0_pred`。

### 5.4 `shift` 的直观意义

DiffSynth-Studio 中多个 Flow Match 模板会对 `sigma` 做变换：

```python
sigmas = shift * sigmas / (1 + (shift - 1) * sigmas)
```

当 `shift > 1` 时，中间区域的 `sigma` 会被抬高。例如：

```text
原始 sigma = 0.5, shift = 5
变换后 sigma = 5 * 0.5 / (1 + 4 * 0.5)
             = 2.5 / 3
             = 0.833
```

直观理解：采样过程会在更高噪声、更全局的阶段停留更久。

这对视频和高分辨率图像很重要，因为高噪声阶段更像是在决定整体结构、运动和布局；低噪声阶段更像是在补细节。如果过早进入低噪声区，模型可能还没把大结构定好，后面再补细节就会变得困难。

### 5.5 不同 FlowMatch 模板的差异

`FlowMatchScheduler` 支持多个模板。它们的 `step()` 基本相同，主要差异在 `set_timesteps()` 如何生成 `sigmas/timesteps`。

| 模板 | 主要差异 | 直观影响 |
| --- | --- | --- |
| `Wan` | `sigma_min=0`，默认 `shift=5`，最后不显式包含 `sigma=0`，最后一步由 `to_final` 或末步逻辑落到 0。 | 更偏向在高噪声区保留足够步数，适配 Wan 视频模型。 |
| `FLUX.1` | `sigma_min=0.003/1.002`，默认 `shift=3`。 | 末端不完全到 0，贴合 FLUX.1 的训练和推理配置。 |
| `Qwen-Image` | 可根据图像 token 数动态计算 shift，并做 terminal shift。 | 分辨率变化时自动改变采样节奏。 |
| `Qwen-Image-Lightning` | 固定 lightning 风格 shift。 | 面向少步或蒸馏配置。 |
| `FLUX.2` | 根据序列长度和步数计算经验 `mu`。 | 高分辨率、不同步数下更稳定。 |
| `Z-Image` | 默认 `shift=3`，可对指定 timestep 做对齐。 | 方便贴合模型发布的 timestep 设置。 |
| `LTX-2` | 支持 stage2 / distilled stage1 的特殊固定 sigma。 | 两阶段或蒸馏视频模型需要固定轨迹。 |
| `ERNIE-Image` | 默认 `shift=3`。 | 保持 ERNIE-Image 对应采样节奏。 |
| `ACE-Step` | 默认 8 步。 | 明显面向少步生成。 |
| `Ideogram4` | 根据图像分辨率构造 logSNR 分布。 | 分辨率越高，噪声日程越会变化。 |
| `HiDream-O1-Image` | dev 模式使用固定 timestep 列表。 | 固定少步轨迹，贴合模型发布配置。 |

结论：这些模板大多不是完全不同的 sampler，而是“同一个 Flow Match Euler 更新公式 + 不同噪声日程”。

## 6. DiffSynth-Studio 中的 DDIMScheduler

源码：`diffsynth/diffusion/ddim_scheduler.py`

### 6.1 DDIM 的核心动作：先估计干净样本，再重组

DDIM 面向传统扩散模型。对于 `epsilon` 预测，当前 noisy latent 满足：

```text
x_t = sqrt(alpha_t) * x0 + sqrt(1 - alpha_t) * epsilon
```

如果模型预测出了 `epsilon_pred`，就可以估计：

```text
x0_pred = (x_t - sqrt(1 - alpha_t) * epsilon_pred) / sqrt(alpha_t)
```

然后把这个估计到的干净样本，按下一步噪声强度重新组合：

```text
x_prev = sqrt(alpha_prev) * x0_pred + sqrt(1 - alpha_prev) * epsilon_pred
```

这就是确定性 DDIM 的主要直觉：

```text
先问：如果当前脏图是由某个干净图加噪得到的，那么那个干净图大概是什么？
再问：如果要回到更低噪声的一层，应该把这个干净图和多少噪声重新混合？
```

### 6.2 DiffSynth 里的线性组合实现

仓库实现没有显式写出 `x0_pred`，而是把公式整理成：

```python
prev_sample = sample * weight_x + model_output * weight_e
```

`prediction_type == "epsilon"` 时：

```python
weight_e = sqrt(1 - alpha_prev) - sqrt(alpha_prev * (1 - alpha_t) / alpha_t)
weight_x = sqrt(alpha_prev / alpha_t)
prev_sample = sample * weight_x + model_output * weight_e
```

这和“先估计 `x0_pred` 再重组”是等价的，只是减少了中间变量。

### 6.3 DDIM 数字例子

假设：

```text
x0 = 2
epsilon = 10
alpha_t = 0.25
alpha_prev = 0.64
```

先加噪到当前层：

```text
x_t = sqrt(0.25) * 2 + sqrt(0.75) * 10
    = 9.66
```

如果模型准确预测 `epsilon_pred = 10`：

```text
x0_pred = (9.66 - sqrt(0.75) * 10) / sqrt(0.25)
        = 2
```

下一层更干净，`alpha_prev=0.64`：

```text
x_prev = sqrt(0.64) * 2 + sqrt(0.36) * 10
       = 0.8 * 2 + 0.6 * 10
       = 7.6
```

`x_prev=7.6` 仍然不是干净样本，但比 `x_t=9.66` 更接近 `x0=2`。多走几步后，`alpha` 继续变大，噪声权重继续变小，最终靠近干净 latent。

### 6.4 DDIM 与 DDPM 的区别

DDPM 的反向过程通常会重新采样噪声：

```text
x_prev = mean(x_t, epsilon_pred, t) + std(t) * random_noise
```

DDIM 在 `eta=0` 的常见形式下是确定性的：

```text
x_prev = deterministic_function(x_t, epsilon_pred, t)
```

直观差异：

| 方法 | 每一步是否重新加随机噪声 | 结果特点 |
| --- | --- | --- |
| DDPM ancestral | 是 | 多样性更强，但步数通常更多，复现路径受随机项影响。 |
| DDIM eta=0 | 否 | 更快、更稳定、同 seed 更可复现。 |

DiffSynth-Studio 当前 `DDIMScheduler.step()` 是确定性路径，没有额外 ancestral noise 项。

## 7. HiDreamO1FlashScheduler：先估计干净样本，再重新加噪

源码：`diffsynth/diffusion/flow_match.py`

`HiDreamO1FlashScheduler` 继承 Flow Match 的 timestep 设置思想，但 `step()` 和普通 Flow Euler 不一样。

源码核心：

```python
denoised = sample - model_output * sigma
noise = clip_noise(torch.randn(...))
sample = sigma_next * noise * noise_scale + (1.0 - sigma_next) * denoised
```

第一行：

```text
denoised = sample - model_output * sigma
```

对应 Flow Match 里的：

```text
x0_pred = x_sigma - sigma * velocity
```

后面重新注入噪声：

```text
x_next = sigma_next * clipped_noise * noise_scale + (1 - sigma_next) * x0_pred
```

直观理解：

```text
普通 Flow Euler:
    沿模型预测的速度场走一小步。

Flash re-noise:
    先把当前点投影回“干净样本估计”，再按下一噪声级别重新混入随机噪声。
```

数字例子：

```text
sample = 10
sigma = 1.0
sigma_next = 0.8
model_output = 3
clipped_noise = 0.2
noise_scale = 7.5

denoised = 10 - 3 * 1.0 = 7
x_next = 0.8 * 0.2 * 7.5 + 0.2 * 7
       = 2.6
```

这类方法往往和特定少步模型、蒸馏模型或官方配置绑定更紧。因为模型训练或蒸馏时已经适配了这种 re-noise 轨迹，随意替换成普通 Euler 不一定更好。

## 8. 常见采样器的原理差异

### 8.1 Euler：只相信当前位置的一阶方向

Euler 是最简单的数值积分：

```python
def euler_step(x, derivative, t, t_next):
    dt = t_next - t
    return x + derivative * dt
```

Flow Match 的 step 就是 Euler 在 `sigma` 空间里的形式：

```python
def flow_match_step(x, velocity, sigma, sigma_next):
    return x + velocity * (sigma_next - sigma)
```

直观理解：

```text
当前位置的模型输出是一根切线。
Euler 认为下一小段路就沿这根切线走。
```

优点：

```text
每步只调用一次模型，快、简单、显存和工程成本低。
```

缺点：

```text
如果轨迹弯得厉害，或者步长太大，只看当前位置斜率会偏离真实轨迹。
```

### 8.2 Heun：先预测，再校正

Heun 可以看作 Euler 的增强版：

```python
def heun_step(model, x, t, t_next, cond):
    dt = t_next - t

    d1 = model(x, t, cond)
    x_predict = x + d1 * dt

    d2 = model(x_predict, t_next, cond)
    x_next = x + 0.5 * (d1 + d2) * dt
    return x_next
```

直观理解：

```text
Euler: 只问出发点的方向。
Heun: 先按出发点方向试走一步，再问试走后的方向，最后取两个方向的平均。
```

数字例子：

```text
x = 10
t = 1.0
t_next = 0.8
dt = -0.2
d1 = 3

Euler:
x_predict = 10 + 3 * (-0.2) = 9.4

如果到 9.4 后模型发现方向变成 d2 = 2:
Heun:
x_next = 10 + 0.5 * (3 + 2) * (-0.2)
       = 9.5
```

Heun 更稳的原因是它补偿了“轨迹弯曲”带来的误差。但代价也直接：每步通常需要两次模型调用，所以同样步数下大约更慢。

### 8.3 DPM-Solver：利用扩散 ODE 结构做高阶近似

DPM-Solver 的目标是少步数下仍然保持质量。它不是简单地“多问一次模型”，而是利用扩散 ODE 的数学结构，在合适的时间变量中做高阶求解。

直观上可以理解为：

```text
Euler:
    只用当前斜率。

DPM-Solver:
    知道扩散方程里有一部分变化形式是固定的，
    这部分可以更精确地处理；
    对模型预测项，再用一阶、二阶或三阶近似。
```

一个极简二阶形状可以写成：

```python
def two_step_history_update(x, d_now, d_prev, h):
    # 这是帮助理解的 Adams-Bashforth 形状，不是完整 DPM-Solver 公式。
    return x + h * (1.5 * d_now - 0.5 * d_prev)
```

数字例子：

```text
x = 10
h = -0.2
d_prev = 4
d_now = 3

x_next = 10 + (-0.2) * (1.5 * 3 - 0.5 * 4)
       = 10 - 0.2 * 2.5
       = 9.5
```

这个例子只展示“利用历史方向修正当前方向”的直觉。真实 DPM-Solver 会在 `logSNR`、`sigma` 或 `lambda` 等参数化下使用严格推导的系数，因此不能简单把上面的伪代码复制到任意模型里。

适用特点：

| 特点 | 说明 |
| --- | --- |
| 少步质量好 | 10 到 30 步区间常比简单 Euler 更强。 |
| 参数化敏感 | 必须知道模型预测的是 `epsilon`、`x0`、`v` 还是 score。 |
| 实现复杂 | 时间变量、噪声 schedule、模型输出转换都要对齐。 |

### 8.4 UniPC：统一的预测-校正框架

UniPC 的名字里 PC 指 Predictor-Corrector。

直观理解：

```text
Predictor:
    根据当前点和历史信息预测下一点。

Corrector:
    用下一点附近的模型信息修正这个预测。
```

简化形式：

```python
def unipc_step(model, x, t, t_next, history, cond):
    d_pred = predictor(history, x, t, t_next)
    x_pred = x + d_pred

    d_corr = model(x_pred, t_next, cond)
    x_next = corrector(x, d_pred, d_corr, history)
    return x_next
```

它和 Heun 的相似点：

```text
都包含“先预测，再校正”的思想。
```

差异：

```text
Heun 更像固定的二阶预测校正。
UniPC 更系统地统一多步历史、预测器和校正器，适配扩散模型的噪声参数化。
```

因此 UniPC 经常在少步数采样中表现稳定，但它也和 DPM-Solver 一样，需要正确处理模型预测类型和噪声时间变量。

### 8.5 DDPM ancestral：每一步都保留随机性

DDPM ancestral sampling 的典型形式是：

```python
def ddpm_ancestral_step(x_t, eps_pred, t):
    mean = posterior_mean(x_t, eps_pred, t)
    std = posterior_std(t)
    return mean + std * torch.randn_like(x_t)
```

直观理解：

```text
每一步不是只走确定路径，而是在合理范围内重新掷一次随机项。
```

优点是多样性强，路径更贴近原始扩散马尔可夫链；缺点是步数通常较多，速度慢，且随机项会影响复现。

### 8.6 DDIM：确定性地穿过同一组噪声层

DDIM 可以看成把 DDPM 的随机反向链改写成确定性路径：

```python
def ddim_step(x_t, eps_pred, alpha_t, alpha_prev):
    x0 = (x_t - (1 - alpha_t) ** 0.5 * eps_pred) / (alpha_t ** 0.5)
    x_prev = (alpha_prev ** 0.5) * x0 + ((1 - alpha_prev) ** 0.5) * eps_pred
    return x_prev
```

直观理解：

```text
DDPM:
    每一步从一个分布里采样。

DDIM:
    在同一组边缘分布之间选一条确定性路径。
```

这也是 DDIM 常用于图像编辑、反演、可复现实验的原因。

## 9. ODE 与 SDE：确定路径和随机路径

采样器还可以从 ODE / SDE 角度理解。

| 类型 | 是否重新注入随机噪声 | 直观理解 | 例子 |
| --- | --- | --- | --- |
| ODE sampler | 通常否 | 给定初始噪声后，走一条确定路径。 | DDIM eta=0、Euler ODE、Heun、DPM-Solver、FlowMatch Euler |
| SDE / ancestral sampler | 是 | 每一步除了去噪，还重新采样一点随机扰动。 | DDPM ancestral、Euler ancestral、Flash re-noise |

确定性路径的优点：

```text
同 seed、同 prompt、同配置下更容易复现。
图像编辑和 inversion 更容易对齐。
```

随机路径的优点：

```text
多样性更强。
某些少步蒸馏模型会专门依赖重新加噪的轨迹。
```

但随机并不天然更好。关键仍然是模型训练时见过什么轨迹、采样时是否走相同或兼容的轨迹。

## 10. 为什么步数不是越多越好，也不是越少越好

采样步数控制的是轨迹被切成多少段。

```text
步数太少:
    每一步跨度大，模型预测误差会被放大。
    简单 Euler/DDIM 容易跳过关键结构调整。

步数适中:
    每一步跨度可控，模型有机会逐渐修正结构和细节。

步数过多:
    每步调用模型都要耗时。
    如果日程和模型不匹配，更多步不一定带来更好质量。
    对蒸馏少步模型，强行增加步数甚至可能偏离训练轨迹。
```

一个实用判断：

| 模型类型 | 步数选择倾向 |
| --- | --- |
| 普通未蒸馏扩散模型 | 往往需要 20 到 50 步甚至更多，取决于 sampler。 |
| 高阶 sampler | 可以用较少步数逼近更细步的轨迹。 |
| Lightning / Turbo / Flash / distilled 模型 | 通常应该优先遵循官方少步配置。 |
| 视频模型 | 单步计算很重，步数、帧数、分辨率、VAE、DiT 前向和条件编码都会显著影响耗时。 |

## 11. 不同采样器横向对比

| 采样器 | 常见模型输出 | 是否随机 | 每步模型调用 | 核心动作 | 优点 | 代价 |
| --- | --- | --- | --- | --- | --- | --- |
| DDPM ancestral | `epsilon` | 是 | 1 | 预测均值后加随机噪声 | 多样性高，贴近原始训练链 | 通常需要较多步 |
| DDIM | `epsilon` / DDPM `v` | 通常否 | 1 | 估计 `x0` 后按下一噪声层重组 | 稳定、快、可复现 | 少步时可能不够锐或结构不足 |
| Euler | score / velocity / ODE derivative | 可确定也可 ancestral | 1 | `x += d * dt` | 简单、快、工程成本低 | 一阶精度，步长大时误差明显 |
| Heun | score / velocity | 通常否 | 2 | Euler 预测后再平均校正 | 比 Euler 稳，少步质量常更好 | 每步多一次模型调用 |
| DPM-Solver | `epsilon` / `x0` / score 等 | 通常否 | 1 或多阶历史 | 利用扩散 ODE 结构做高阶求解 | 少步质量强 | 实现复杂，参数化敏感 |
| UniPC | `epsilon` / `x0` / score 等 | 通常否 | 1 或带校正调用 | predictor-corrector + 历史信息 | 少步稳定，适配面广 | 时间变量和输出转换要严格对齐 |
| FlowMatch Euler | `noise - data` velocity | 否 | 1 | `x += v * delta_sigma` | 适配 Wan/FLUX/Qwen 等新模型 | 不能直接用于 DDPM 目标 |
| Flash re-noise | Flow velocity | 是 | 1 | 估计 `x0` 后重新加噪 | 适合特定少步/蒸馏配置 | 随机性更强，和模型绑定紧 |

## 12. 最小实现形式

下面是帮助理解的最小伪代码，省略 CFG、batch、dtype、device、guidance rescale、模型输入缩放等工程细节。

### 12.1 DDIM

```python
def ddim_step(x_t, eps_pred, alpha_t, alpha_prev):
    x0 = (x_t - (1 - alpha_t) ** 0.5 * eps_pred) / (alpha_t ** 0.5)
    x_prev = (alpha_prev ** 0.5) * x0 + ((1 - alpha_prev) ** 0.5) * eps_pred
    return x_prev
```

### 12.2 Flow Match Euler

```python
def flow_match_step(x, velocity, sigma, sigma_next):
    return x + velocity * (sigma_next - sigma)
```

### 12.3 Heun

```python
def heun_step(model, x, t, t_next, cond):
    dt = t_next - t
    d1 = model(x, t, cond)
    x_euler = x + d1 * dt
    d2 = model(x_euler, t_next, cond)
    return x + 0.5 * (d1 + d2) * dt
```

### 12.4 DPM-Solver 的二阶直觉

```python
def dpm_solver_like_step(x, d_now, d_prev, h):
    # 仅展示“利用历史导数”的形状；完整 DPM-Solver 需要专门系数。
    d = 1.5 * d_now - 0.5 * d_prev
    return x + h * d
```

### 12.5 UniPC 的预测校正直觉

```python
def unipc_like_step(model, x, t, t_next, history, cond):
    x_pred = predictor(x, t, t_next, history)
    d_corr = model(x_pred, t_next, cond)
    x_next = corrector(x, x_pred, d_corr, history)
    return x_next
```

### 12.6 Flash re-noise

```python
def flash_step(x, velocity, sigma, sigma_next, noise_scale, clip_std):
    denoised = x - velocity * sigma
    noise = torch.randn_like(x)
    noise = clip_noise(noise, clip_std)
    return sigma_next * noise * noise_scale + (1 - sigma_next) * denoised
```

## 13. 为什么不能随意替换采样器

采样器和模型之间至少有四个绑定点。

### 13.1 输出含义绑定

同样一个张量 `model_output`，不同模型里含义不同：

```text
DDIM epsilon 模型:
    model_output = epsilon_pred

Flow Match 模型:
    model_output = noise - x0

DDPM v-prediction 模型:
    model_output = sqrt(alpha) * noise - sqrt(1 - alpha) * x0
```

如果把 Flow Match 的 `velocity` 当成 DDIM 的 `epsilon`，`x0_pred` 公式会错。

### 13.2 时间坐标绑定

DDIM 使用的是 `alpha_bar_t`：

```text
x_t = sqrt(alpha) * x0 + sqrt(1 - alpha) * noise
```

Flow Match 使用的是 `sigma`：

```text
x_sigma = (1 - sigma) * x0 + sigma * noise
```

二者都描述“干净程度”，但不是同一坐标。

### 13.3 噪声日程绑定

模型训练时见过某种 timestep / sigma 分布。推理时如果日程偏离太多，模型可能在不熟悉的噪声区间工作。

例如 Wan 使用 `shift=5`，不是随便选择的常数。它改变了采样过程在高噪声和中噪声区域的停留方式，影响视频整体运动、结构和细节的形成节奏。

### 13.4 蒸馏轨迹绑定

少步模型通常不是普通模型简单减少步数，而是经过蒸馏或特殊训练，使模型适应固定步数、固定 timestep 或特殊 re-noise 轨迹。

因此：

```text
普通模型 + 强行 4 步:
    往往质量明显下降。

蒸馏模型 + 官方 4 步:
    可能效果很好。

蒸馏模型 + 随意改成 50 步:
    不一定更好，甚至可能变差。
```

## 15. 实际选择建议

| 场景 | 建议 |
| --- | --- |
| Wan / S2V / FLUX / Qwen / Z-Image / LTX-2 等 Flow Match 模型 | 优先使用对应 `FlowMatchScheduler` 模板，不要直接换 DDIM。 |
| Stable Diffusion / SDXL 这类传统扩散模型 | 使用 DDIM 或与 `epsilon` / `v_prediction` 兼容的 DPM-Solver、UniPC。 |
| 追求速度 | 优先选择每步一次模型调用的 Euler / DDIM / FlowMatch Euler，并减少步数。 |
| 追求少步质量 | 考虑 DPM-Solver、UniPC、Heun，前提是实现和模型参数化匹配。 |
| 追求稳定复现 | 使用确定性采样器，固定 seed、scheduler、timestep、CFG 和精度配置。 |
| 使用 Flash / Lightning / Turbo / 蒸馏模型 | 优先遵循官方步数、timestep 和 scheduler，不要盲目增加步数。 |
| 视频生成或视频训练 | 单步成本很高，采样器步数只是耗时的一部分，帧数、分辨率、VAE、DiT 前向和条件编码都会显著影响速度。 |

## 16. 关键结论

1. 采样是在 latent 空间中求解一条从噪声到数据的轨迹，不是一次性去噪。
2. 训练时的“采样”主要是采数据、采噪声、采噪声层；它通常是在真实加噪轨迹上做单点监督，不是每次都完整跑一条反向生成链。
3. 推理时没有真实 `x0`，只能从纯噪声开始，让模型输出局部修复方向，再由采样器逐步移动。
4. 一步到 `x0` 在模型完美时成立；现实中它是一次大跨度猜测，误差会直接变成最终结果。
5. 多步采样把大跨度生成拆成多个局部修复问题，每一步都能在更清楚的 latent 上重新判断方向。
6. `scheduler` 决定经过哪些噪声层，`sampler` 决定每层之间怎么移动。
7. DDIM 的核心是“预测噪声 -> 估计干净样本 -> 按下一噪声层重组”。
8. Flow Match 的核心是“预测速度场 -> 在 sigma 空间反向积分”。
9. Euler 简单快速但只是一阶；Heun、DPM-Solver、UniPC 用校正或高阶近似减少少步误差。
10. ODE 类采样器更确定，SDE / ancestral / re-noise 类采样器会重新注入随机性。
11. 固定间隔训练或一步训练是可行方向，但通常需要少步蒸馏、一致性训练或专门轨迹约束；它不是普通多噪声层训练的直接替代。
12. 采样器不能随意跨模型替换，因为模型输出含义、时间坐标、噪声日程和蒸馏轨迹都可能不同。
13. 对 DiffSynth-Studio 当前的 Wan2.2-S2V-14B 这类 Wan 视频模型，应优先保持 `FlowMatchScheduler("Wan")` 这一类 Flow Match 采样路径。
